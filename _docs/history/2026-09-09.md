### 메모리 복구와 확인

v1의 FULL_FT S0는 Windows available commit 6GiB 기준으로 중단됐다. v2는 외부 2초 polling 사이의 짧은 활성 메모리 저하를 놓쳐 guard PASS였으나, 단계별 로그에서 기준 미달을 확인해 후속 실행을 중단했다. 따라서 v2 PASS를 안전한 본 학습의 증거로 사용하지 않는다.

v3는 best-state를 FP32 파일 매핑에 보관하고, 각 micro backward 및 optimizer 직후/정리 후에 동일한 6GiB 기준을 직접 검사한다. 첫 v3 S0도 첫 optimizer 직후 5.495GiB에서 즉시 실패했고, 기록은 `runs/peft_fullft_reference_v3/failed_attempts/attempt01`에 보존했다. 학습 조건과 안전 기준을 낮추지 않았다.

오늘 생성된 중복 브라우저 MCP helper 14묶음이 합계 약 2.745GiB private commit을 사용했다. Codex parent, 정확한 PID/생성시각, node/cmd 외 자식이 없음을 확인하고 정리했다. 사용자 브라우저나 다른 앱을 종료하지 않았다. 계획된 63개 helper 중 21개를 직접 종료했고 나머지는 함께 자연 종료했으며, 전체 63개 PID가 남아 있지 않음을 재확인했다. Windows available commit은 10.376→13.035GiB로 증가했다. 계획/실행 영수증은 `unused_browser_helpers_plan.json`, `unused_browser_helpers_cleanup.json`에 있다. 이것은 이번 안전 중단의 자원 원인에 대한 관측이며, 과거 PC 프리즈 원인의 확정은 아니다. 드라이버·Defender·pagefile 등 OS 설정은 변경하지 않았다.

정리 후 v3 S0 6/6 PASS. FULL_FT Bike 활성 단계 최소 commit 8.174GiB, Household 8.018GiB. Bike의 step0 예측, sampler, V 예측, 최종 체크포인트 SHA가 v2와 모두 같아 수치적 동일성을 확인했다(`recovery_equivalence.json`). Core CPU 검사 38개 및 분석 검사 9개 PASS. 계절성/ridge의 V 선택도 CPU guard에서 완료했다.
