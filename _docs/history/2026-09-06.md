## 포스터 섹션 익명화 + 루트 커밋 재작성

`_docs/reference/time_series_research_dossier_20260906.md` 의 포스터 섹션 헤더 4줄에
발표자 실명과 원본 PDF 파일명이 그대로 들어 있었고, 저장소가 public 이라 이미 GitHub 에
공개된 상태였다. 실명을 지웠고, 학회 포스터 번호도 프로그램과 대조하면 발표자 역추적이
가능해서 함께 지웠다. 문서 등장 순서대로 일련번호를 새로 매겼다.

| Before | After |
| --- | --- |
| `### P2-64-{이름}(1).pdf — 변수별 신뢰도 기반 gradient 조정` | `### 포스터 1 — 변수별 신뢰도 기반 gradient 조정` |
| `### P2-65-{이름}.pdf — Retrieval-Guided Residual Correction` | `### 포스터 2 — Retrieval-Guided Residual Correction` |
| `### P1-65-{이름}.pdf — Adaptive Reference Memory` | `### 포스터 3 — Adaptive Reference Memory` |
| `### P1-64-{이름} (1).pdf — Hurdle Decomposition` | `### 포스터 4 — Hurdle Decomposition` |

본문 내용은 건드리지 않았다. 바뀐 것은 헤더 4줄뿐이다.

`PROJECT_LOG.md` 의 "두 파일은 업로드 원본 그대로다 … 내용을 고치지 않는다" 문장이 이
수정으로 사실과 어긋나게 되어, 무엇을 왜 고쳤는지 명시하도록 같이 갱신했다.

### git 히스토리 재작성

새 커밋으로 지우면 최신 파일에서만 사라지고 최초 커밋 `477a78b` 를 열면 실명이 그대로
보인다. 커밋이 그 하나뿐이었으므로 루트 커밋 자체를 `--amend` 로 다시 쓰고
`--force-with-lease` 로 push 했다. 사용자에게 파괴적 액션임을 알리고 선택을 받았다.

- 재작성 전 백업: 세션 scratchpad 에 `dossier_ORIGINAL_with_names.md` 와
  `mltimeseries_before_rewrite.bundle` (저장소 전체) 를 남겼다. 저장소 안에는 두지 않았다.

### force-push 만으로는 부족했다 — 원격 저장소 삭제 후 재생성

force-push 는 브랜치 포인터만 옮긴다. 참조가 끊긴 옛 커밋 `477a78b` 는 GitHub 에 그대로
남아 SHA 로 계속 열렸다. push 직후 실제로 확인한 값이다.

| 대상 | force-push 직후 |
| --- | --- |
| `raw.githubusercontent.com/.../477a78b/...dossier...md` | HTTP 200, 실명 4건 그대로 |
| `github.com/.../commit/477a78b` | HTTP 200 |

그래서 저장소를 지우고 다시 만들었다. 새 저장소는 저장소 자체가 새 객체 저장소라 옛
커밋이 존재하지 않는다.

삭제 전 확인한 것 — issue·PR·release·star·fork 전부 0, 원격 브랜치는 `main` 하나,
원격 SHA 가 로컬 HEAD 와 동일. 잃을 원격 전용 자산이 없음을 확인한 뒤 진행했다.
로컬 저장소와 scratchpad 의 `mltimeseries_CLEAN_3959a2d.bundle` (`git bundle verify`
로 complete history 확인) 이 백업이다.

`gh repo delete` 는 토큰에 `delete_repo` scope 이 없어 HTTP 403 으로 막혔고, 브라우저
인증이 필요해 사용자가 직접 삭제했다. 재생성·push 는 다시 CLI 로 했다.

```
gh repo create CanelE452/mltimeseries --public --description "..."   # 기존 설명·공개설정 유지
git push -u origin main
```

- 새 저장소 `createdAt` 2026-09-06T02:15:06Z, default branch `main`, visibility PUBLIC.
- push 결과 `* [new branch] main -> main`, 원격 `main` = `3959a2d` (로컬과 동일).
- 새 main 원본을 raw 로 받아 이름 검색 0건 확인.
- 삭제 직후 `github.com/.../commit/477a78b` 는 404 로 바뀌었으나 raw CDN 은 한동안
  200 을 반환했다. `X-Cache: HIT` / `Source-Age: 268` / `max-age=300` 으로, origin 이
  아니라 Fastly 엣지 캐시였다. 캐시 만료까지 폴링해 404 를 확인했다.
