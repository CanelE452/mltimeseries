# 19b. 정상 브라우저 다운로드 경로 사용

2026-09-08. 원 전체 및 작은 urllib POST 두 번 모두 HTTP 헤더 전 30초 timeout이었다. 자동 POST 반복은 중단했다. 공식 Chrome 양식에 같은 작은 요청을 제출했을 때 3.277초 뒤 download 이벤트가 관찰되었다. 이 시점에서 파일 내용·전체 coverage는 아직 미검증이다.

사용자가 승인한 두 계열 자료 확보를 정상 공식 브라우저 양식으로 이어간다. 원19의 series/관측 기간/전체 vintage 선택/경계일/units/file_type/file_format은 동일하다. ZIP16MiB씩·전체 해제128MiB 한도와 안전한 멤버 검사도 유지한다. 원 urllib 실패 자료와 작은 probe는 보존하며, 최종 분석은 원래 전체 범위를 충족한 두 archive만 사용한다.

브라우저 다운로드는 fetch.py가 성공한 것으로 기록하지 않는다. 실제 UI에서 확인한 요청 필드·download 이벤트·받은 파일 위치·크기·SHA와 수신 기록을 별도로 남긴다. 브라우저 자체는 CPU child guard의 측정 대상이 아니므로 해당 브라우저의 peak 메모리나 GPU 사용량을 guard로 측정했다고 주장하지 않는다. GPU 학습은 계속 0회다.

이것은 자료 전송 경로 변경이며 표본·평가·모델 선택 규칙의 변경이 아니다. API key·계정·인증 우회는 사용하지 않는다. 프로그램 요청과 브라우저 경로의 차이 원인은 아직 확정하지 않는다.
